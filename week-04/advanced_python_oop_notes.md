یادداشت‌های جامع مباحث تکمیلی شیءگرایی در پایتون

این سند یک خلاصه‌ی ساختاریافته و آموزشی از مفاهیم پیشرفته‌ی شیءگرایی (OOP) در پایتون است. در این فایل تلاش شده تا مفاهیم به زبانی ساده همراه با نکات استخراج‌شده از کدها و تمرین‌های عملی (مانند پروکسی، وارون‌پیما و دکوراتورها) گردآوری شود تا به عنوان یک مرجع سریع و کامل قابل استفاده باشد.

۱. کپسوله‌سازی و کنترل دسترسی (Encapsulation)

در پایتون بر خلاف زبان‌هایی مثل جاوا، کنترل دسترسی بیشتر بر اساس قرارداد بین برنامه‌نویسان است تا محدودیت‌های سخت‌گیرانه سیستم.

عمومی (Public): متغیرهای عادی (مثل self.name). از همه‌جا قابل دسترسی هستند.

محافظت‌شده (Protected): پیشوند یک زیرخط (مثل self._age). یک هشدار به برنامه‌نویس دیگر است که: "این متغیر برای استفاده داخلی کلاس است، مستقیم به آن دست نزن!" اما زبان پایتون جلوی شما را نمی‌گیرد.

خصوصی (Private): پیشوند دو زیرخط (مثل self.__password). پایتون با مکانیزم Name Mangling نام آن را پشت صحنه به _ClassName__password تغییر می‌دهد تا دسترسی مستقیم و تصادفی به آن سخت شود (جلوگیری از تداخل در ارث‌بری).

💡 روش استاندارد پایتون: استفاده از Properties (به جای Getter/Setter مجزا)

اگر می‌خواهید موقع مقداردهی به یک متغیر، شرطی را چک کنید (اعتبارسنجی)، یا یک ویژگی داشته باشید که مقدارش در لحظه محاسبه می‌شود، از دکوراتور @property استفاده کنید.

class Robot:
    def __init__(self, energy):
        self.energy = energy # پایتون به صورت خودکار متد setter زیر را صدا می‌زند

    # ۱. تعریف Getter (گرفتن مقدار)
    @property
    def energy(self): 
        return self.__energy

    # ۲. تعریف Setter (تغییر مقدار همراه با اعتبارسنجی)
    @energy.setter
    def energy(self, value): 
        if value < 0: 
            raise ValueError("انرژی نمی‌تواند منفی باشد")
        self.__energy = value


نکته آموزشی: هرگز از روش قدیمی x = property(get_x, set_x) استفاده نکنید چون کُد را کثیف و ناخوانا می‌کند.

۲. خودآزمایی (Introspection) و بازتاب (Reflection)

خودآزمایی: یعنی برنامه در زمان اجرا از خودش بپرسد "این متغیر چیست؟ از چه کلاسی است؟ چه متدهایی دارد؟" بازتاب: یعنی یک قدم جلوتر برویم و در زمان اجرا، ویژگی‌های شیء را تغییر دهیم یا ویژگی جدید اضافه کنیم.

توابع مهم خودآزمایی:

type(obj): نوع/کلاس شیء را می‌دهد. (نکته: در پایتون با پاس دادن ۳ آرگومان به type می‌توان در زمان اجرا یک کلاس جدید ساخت!)

dir(obj): لیست تمام متدها و متغیرهای شیء (حتی مخفی‌ها) را می‌دهد.

isinstance(obj, class_name): می‌پرسد آیا این شیء از این کلاس (یا فرزندانش) هست یا خیر؟ (خروجی True/False).

hasattr(obj, 'name'): می‌پرسد آیا این شیء متغیری به اسم 'name' دارد؟

نکته اضافه شده: vars(obj) دیکشنری تمام متغیرهای ساخته شده داخل شیء (__dict__) را به شما می‌دهد.

توابع مهم بازتاب (Reflection):

getattr(obj, 'name', default): گرفتن مقدار متغیر با دادن اسم آن به صورت رشته (String).

setattr(obj, 'name', value): ساختن متغیر جدید یا تغییر متغیر قبلی با استفاده از رشته.

💡 نکات طلایی از تمرین پروکسی (Proxy Pattern):

الگوی پروکسی یعنی یک کلاس واسطه بسازیم که درخواست‌ها را می‌گیرد، روی آن‌ها کاری انجام می‌دهد (مثل شمارش دفعات فراخوانی) و سپس به شیء اصلی پاس می‌دهد.

__getattribute__(self, name): هر بار که بنویسید obj.x، این متد بی‌قید و شرط اجرا می‌شود.

__getattr__(self, name): این متد فقط به عنوان آخرین امید (Fallback) اجرا می‌شود؛ یعنی اگر پایتون کل شیء را گشت و متغیر x را پیدا نکرد، به جای دادن ارور AttributeError، این متد را اجرا می‌کند.

ترفند پروکسی: در کلاس پروکسی، شیء اصلی را مثلا در self._obj ذخیره می‌کنیم. سپس __getattr__ را می‌نویسیم تا اگر متدی روی پروکسی صدا زده شد، آن را با getattr(self._obj, name) از شیء اصلی بگیرد و به کاربر برگرداند.

۳. متدهای جادویی (Dunder Methods)

متدهایی که با __ شروع و تمام می‌شوند. این متدها به شما اجازه می‌دهند رفتار عملگرهای پایتون (مثل +, <, len()) را برای کلاس‌های خودتان تعریف کنید (Operator Overloading).

__str__(self): وقتی شیء را print می‌کنید، این متد اجرا می‌شود (برای نمایش زیبا به کاربر).

__repr__(self): وقتی اسم شیء را در کنسول تایپ می‌کنید اجرا می‌شود (برای نمایش دقیق به برنامه‌نویس جهت دیباگ).

__add__(self, other): تعریف رفتار عملگر +.

__len__(self): وقتی بنویسید len(obj) این متد اجرا می‌شود.

__call__(self, *args): اگر این متد را بنویسید، می‌توانید شیء را مثل یک تابع صدا بزنید! مثلا my_obj().

💡 نکات استخراج‌شده از تمرین‌ها:

تمرین Strint (ارث‌بری از انواع پایه): اگر کلاسی بسازید که از int (عدد صحیح) ارث‌بری کند، خود شیء ذاتاً تبدیل به یک عدد می‌شود و نیازی به تعریف __init__ و ذخیره مقدار در متغیر داخلی ندارید! فقط کافیست مثلاً __add__ را بازنویسی کنید تا رفتار جمع اعداد تغییر کند.

مقایسه‌ها (__lt__ برای کوچکتر، __eq__ برای مساوی): همیشه در خط اول این متدها بنویسید if not isinstance(other, MyClass): return NotImplemented. این کار باعث می‌شود اگر کسی خواست کلاس شما را با مثلاً یک رشته مقایسه کند، پایتون کرش نکند و منطقی رفتار کند.

تمرین وارون‌پیما (پروتکل Iteration): برای اینکه یک کلاس در حلقه for کار کند باید:

متد __iter__(self) داشته باشد که معمولاً return self می‌کند.

متد __next__(self) داشته باشد که هر بار عنصر بعدی را بدهد.

وقتی عناصر تمام شد، باید دقیقاً ارور raise StopIteration پرتاب کند تا حلقه for بفهمد باید متوقف شود.

۴. دکوراتورها (Decorators)

دکوراتور یعنی یک تابع را بگیریم، دور آن یک پوسته (Wrapper) بکشیم تا قبل یا بعد از اجرایش کار اضافه‌ای (مثل چک کردن پسورد، لاگ گرفتن، زمان‌سنجی) انجام دهیم، بدون اینکه کدهای تابع اصلی را دستکاری کنیم.

پایه و اساس: در پایتون توابع شیء هستند؛ یعنی می‌شود آن‌ها را درون یک متغیر ریخت یا به عنوان ورودی به تابع دیگری داد.

💡 ساختار استاندارد و مهندسی دکوراتورها:

نکته بسیار مهم: همیشه باید از @wraps استفاده کنید تا اسم و توضیحات (Docstring) تابع اصلی با تابع Wrapper جایگزین و گم نشود.

مدل اول: دکوراتور ساده (بدون آرگومان) - ۲ لایه

from functools import wraps

def my_decorator(func):                   # لایه ۱: تابع اصلی را می‌گیرد
    @wraps(func)                          # *حیاتی*: حفظ هویت تابع اصلی
    def wrapper(*args, **kwargs):         # لایه ۲: پوسته محافظ
        print("قبل از اجرا")
        result = func(*args, **kwargs)    # اجرای تابع اصلی
        print("بعد از اجرا")
        return result
    return wrapper

@my_decorator
def say_hello(): pass


مدل دوم: دکوراتور با آرگومان - ۳ لایه (مثل تمرین سنجایش/Validator) اگر دکوراتور شما ورودی می‌گیرد (مثل @repeat(3)):

def repeat(times):                        # لایه ۱: آرگومان دکوراتور را می‌گیرد
    def decorator(func):                  # لایه ۲: تابع اصلی را می‌گیرد
        @wraps(func)
        def wrapper(*args, **kwargs):     # لایه ۳: پوسته محافظ
            for _ in range(times):
                result = func(*args, **kwargs)
            return result
        return wrapper
    return decorator


دکوراتورهای کلاسی: می‌توان از کلاس‌ها هم به عنوان دکوراتور استفاده کرد (با کمک __init__ و __call__). مزیت کلاس این است که می‌تواند وضعیت‌ها (State) را درون خودش ذخیره کند (مثلاً بشمارد تابع چند بار اجرا شده است).

۵. محدوده‌ها و فضای نام (Scopes & Namespaces)

متغیرها در پایتون کجا زندگی می‌کنند و پایتون چطور آن‌ها را پیدا می‌کند؟ قانون LEGB:

L (Local - محلی): متغیرهای ساخته شده داخل خود تابعی که الان در حال اجراست.

E (Enclosing - دربرگیرنده): اگر تابع شما داخل یک تابع دیگر (تودرتو) نوشته شده باشد، پایتون متغیر را در تابع والد می‌گردد.

ترفند: برای تغییر متغیرِ تابعِ والد، قبل از آن بنویسید nonlocal var_name.

G (Global - سراسری): متغیرهای نوشته شده در سطح اصلی فایل (خارج از هر تابع و کلاس).

ترفند: برای تغییر متغیر سراسری از درون یک تابع، قبل از آن بنویسید global var_name.

B (Built-in - پیش‌فرض): دستورات خود پایتون (مثل print و len). اگر متغیری به اسم len بسازید، تابع اصلی پایتون سایه می‌شود (Shadowing) و از کار می‌افتد (کار بسیار اشتباهی است!).

۶. محیط‌های مجازی و مدیریت بسته‌ها (venv & pip)

وقتی روی چند پروژه کار می‌کنید، ممکن است پروژه الف به نسخه ۱ یک کتابخانه نیاز داشته باشد و پروژه ب به نسخه ۲ همان کتابخانه. اگر همه را روی سیستم نصب کنید تداخل ایجاد می‌شود.

راه‌حل: محیط مجازی (Virtual Environment) یک اتاق ایزوله برای هر پروژه که پایتون و کتابخانه‌های خودش را دارد.

ساخت محیط: python -m venv env_name (معمولا اسمش را venv یا .venv می‌گذارند).

فعال‌سازی (ویندوز): venv\Scripts\activate

فعال‌سازی (مک/لینوکس): source venv/bin/activate

غیرفعال‌سازی: deactivate

دستورات مهم pip (Package Installer for Python):

نصب یک کتابخانه: pip install package_name

دیدن لیست کتابخانه‌های نصب شده: pip list

خروجی گرفتن از نیازمندی‌های پروژه (برای انتقال به سیستم دیگر): pip freeze > requirements.txt

نصب دسته‌جمعی وابستگی‌های یک پروژه جدید: pip install -r requirements.txt
